## Problem
The codebase has only **4 spec files** for **48 source files** (~8% coverage). This makes refactoring risky and regressions hard to catch. The GEMINI.md conventions require error handling and proper testing.

## Current Test Files

- `google-tasks-sync.service.spec.ts`
- `project.service.spec.ts`
- `task.service.spec.ts`

## Solution
1. Create spec files for all feature components with basic render/interaction tests
2. Add integration tests for critical user flows (task CRUD, project management)
3. Mock Firebase services consistently using a shared test utility
4. Target minimum 60% code coverage for services, 40% for components

## Acceptance Criteria
- [ ] Every component and service has a corresponding `.spec.ts` file
- [ ] Critical user flows have integration tests
- [ ] `ng test` passes with no failures
- [ ] Code coverage report shows ≥50% overall coverage
