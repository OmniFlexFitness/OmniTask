# OmniTask Mobile (Flutter)

Mobile companion to the [OmniTask web app](../README.md). Shares the
`omnitask-475422` Firebase backend (Auth, Firestore, Cloud Functions, Storage).

> Status: **Phase 0 scaffolding only.** App, design system, and providers are
> stubs. Auth and the read-only task feed land in Phase 1. See
> `../docs/plans/omnitask-mobile-flutter.md` for the full roadmap.

---

## First-time setup

These steps must be run once on a workstation with Flutter installed before the
project will build.

### 1. Install Flutter

```bash
# Pin via FVM (recommended) or Flutter's installer.
flutter --version   # expect 3.27.x stable, Dart 3.6+
```

### 2. Generate the platform directories

The committed scaffold contains `lib/`, `test/`, `pubspec.yaml`, and
`packages/` only. The `android/` and `ios/` directories are produced by
`flutter create` and are **not** committed in this PR — they will land in a
follow-up PR after first generation, signing keys, and `google-services.json` /
`GoogleService-Info.plist` are added.

```bash
cd mobile
flutter create \
  --platforms=android,ios \
  --org com.omniflex \
  --project-name omnitask_mobile \
  .
flutter pub get
```

`flutter create .` is non-destructive for existing files (it leaves `lib/`,
`test/`, and `pubspec.yaml` alone) but it **will** generate `android/` and
`ios/` and may add platform-specific entries to `pubspec.yaml`. Review the
diff carefully before committing.

### 3. Configure FlutterFire

```bash
dart pub global activate flutterfire_cli
flutterfire configure --project=omnitask-475422
```

This generates `lib/firebase_options.dart` (gitignored), drops
`android/app/google-services.json`, and `ios/Runner/GoogleService-Info.plist`
(both gitignored — distribute via secrets manager, not the repo).

### 4. Register Android SHA fingerprints

In the Firebase console for `omnitask-475422`, add SHA-1 and SHA-256 for:

- Local debug keystore (`~/.android/debug.keystore`)
- Play upload key
- Play app-signing key (provided by Play Console after first upload — easy to
  forget)

### 5. iOS push setup (Phase 3 prerequisite)

- Apple Developer Program membership ($99/yr)
- Create an APNS Auth Key in App Store Connect
- Upload the `.p8` to the Firebase console under
  Project Settings → Cloud Messaging → Apple app configuration

Without this, `firebase_messaging` silently fails on iOS.

```bash
cd mobile
flutter pub get
flutter analyze
flutter test
flutter run                       # device picker

flutter run -d emulator-5554      # Android emulator
```

## Stack

- **Flutter** 3.27+ stable, Dart 3.6+
- **State management**: Riverpod 2.x with `riverpod_generator`
- **Routing**: `go_router`
- **FlutterFire**: core, auth, firestore, functions, storage, messaging,
  app_check
- **Native**: google_sign_in, image_picker, file_picker, share_plus,
  receive_sharing_intent, flutter_local_notifications, path_provider, logger
- **Design system**: local path package `packages/omniflex_design_system/`

## Backend reuse

Reads/writes Firestore directly using the same collections and rules as the
web app — no backend changes needed for v1 CRUD. Cloud Functions invoked from
mobile (already deployed):

- `manualGoogleTasksSync`
- `getWorkspaceContacts`, `searchWorkspaceContacts`
- `generateSubtasks`, `suggestTaskPriority`, `suggestDueDate`,
  `enhanceTaskDescription`

Verify each function's region in `functions/src/index.ts` and pass the
matching region to `FirebaseFunctions.instanceFor(region: ...)`.

The only new backend work for v1 is push (Phase 3): a `fcmTokens`
subcollection on user docs and a `sendTaskAssignmentPush` Firestore trigger.

## Brand tokens

`packages/omniflex_design_system/lib/src/colors.dart` is the canonical mobile
palette. Until `tailwind.config.js` carries the full OmniTask palette, the web
and mobile token sets must be kept in sync manually. Source of truth for the
palette lives in `../AGENTS.md` and `../GEMINI.md`.

Hardcoded colors, hardcoded text styles, and hardcoded spacing are forbidden
per `.antigravity/skills/omniflex-code-review/checklist.md` §3.
